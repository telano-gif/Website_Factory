# Build Skill

## Purpose
Turn the approved project artifacts into a polished, responsive, production-ready website.

## Input
`INTAKE.md` + `RESEARCH.md` + `DESIGN_SPEC.md` + `CONTENT.md` + client assets.

## Produce
A complete independent website repository in `04_build/` suitable for GitHub → Vercel deployment.

## Rules
- Inspect the existing project/tooling before choosing or changing architecture.
- Implement the approved design; do not substitute a generic template.
- Build component-by-component, validating as you go.
- Use real supplied/approved imagery and assets; never fabricate company assets.
- Preserve factual content exactly enough to avoid changing claims.
- Implement responsive behaviour, accessibility fundamentals, interaction/motion and performance appropriate to the design.
- Keep dependencies and code complexity minimal.
- Run the project's available lint/build/type checks and fix failures.
- Do not declare completion because the app merely compiles.

## Complete when
The website is fully implemented, locally buildable, visually coherent with `DESIGN_SPEC.md`, content-complete, and ready for QA.

## Handoff
`BUILD_COMPLETE` → QA consumes the built website plus all canonical artifacts.
